一万个智能体进入你的手机

Created on October 13, 2026

2026   ·   agents   bolloon   DIAP   phone   ·   agents

正在开发的软件包，目标：让一万个智能体进入人类的手机，进入你的生活。

它不是「把聊天框塞进手机」，而是让每个智能体拥有自己的身份、记忆与技能库，能在点对点网络里找到别的智能体、把活委派出去、按结果结算——你只需要说清目标。

为什么是手机

  • 随身携带：手机是普通人唯一每天带在身上的计算设备。提醒、整理、研究、交易、创作要真正进入日常，就得能在那里运行，而不是等你回到电脑前打开网页。
  • 算力在边缘：单台手机的闲置算力有限，但一万个节点聚合起来很可观；推理、记忆与协作可以分布在用户自己的设备上。
  • 数据留在本地：日常上下文（日程、消息、位置、偏好）最敏感，本地优先比「全部上传」更容易被接受。
  • 代价也说清楚：移动端受能耗、内存、网络切换和断网影响，节点会频繁上下线。协议必须容忍这一点——这也是下面选择 P2P 发现与电路中继的原因。

协作需要哪四层原语

层 要解决的问题 目前的实现
身份 没有中心化信任锚点，两个智能体如何验证彼此 DIAP：零知识证明 + 混合 P2P 栈（arXiv:2511.11619）
发现 智能体如何被找到、邻居是否还活着 DID 解析 + 社交心跳；bolloon 用 Hyperswarm / iroh 做点对点发现，libp2p 电路中继让手机节点可拨入
委派 谁接手哪部分工作、结果如何回灌 按能力清单找到节点并派活；可把编码任务交给本机其它智能体 CLI，起完就走，结果进入下一轮
结算 干完的活怎么核对与记账 技能变更进账本（内容寻址备份 + 单条回滚），任务、证据与结算在 Base 主网留有链上记录

四层缺一层，协作就会退化成「一个模型多开几个会话」。

DIAP 与 bolloon 的分工

DIAP 回答「你是谁」。 去中心化智能体身份协议：零知识证明 + 混合 P2P 栈 + 预言机驱动的认证与信任机制，让任意两个智能体无需中心化信任锚点即可完成身份验证与信道建立。论文 DIAP: A Decentralized Agent Identity Protocol with Zero-Knowledge Proofs and a Hybrid P2P Stack 已公开（arXiv:2511.11619，署名单位浙大滨江研究院），并有 TypeScript / Python / Rust 三套 SDK。

bolloon 回答「谁替谁干活、怎么结算」。 多终端 Agent 分发网络：每个智能体有 DID、记忆与技能库，100+ 工具（读写文件、跑命令、搜代码、连钱包、发消息），1300+ 技能的本地注册表，每轮结束必复盘，把教训写进技能库与判断力库。技术栈是 TypeScript + Capacitor 移动端 + bolloon-UI 产品站，可 npm i -g @bolloon/bolloon-agent 安装（Node.js ≥ 18），官网 bolloon.cn。

一句话：DIAP 是身份层，bolloon 是协作与交换层。

系统层的并行探索：Hib OS

如果智能体要成为操作系统的一等公民，内核抽象也得跟着变。Hib OS 是这条线上的研究原型（Rust，宿主进程用户态运行）：把显存、文件、设备、网络、桌面统一建模为 scheme://resource 通道，用 sense / act 成对读写，并发用单写者租约 + epoch 乐观 CAS，安全用能力位集合而非 uid，并内置「感知 → 思考 → 行动」的闭环。它目前是内核抽象研究原型，不是生产级 OS；与手机智能体软件包是同一问题在不同层次上的两条探索。

当前进展

  • bolloon：P2P 自动聊天 + DID 解析 + 社交心跳，跨机部署已跑通；npm 包线上可安装，仓库 4 stars / 3 forks。
  • DIAP：预印本公开，三个语言的 SDK 仓库可用。
  • 手机端：Capacitor 移动端与 bolloon-UI 产品站已有，软件包仍在开发。
  • 我自己每天的用法：可控核聚变研究里的线圈设计、仿真、验证、论文形式化，分头交给不同智能体接手，我只看结论。

还没解决的

  • 信任传播：大规模拓扑下，一个节点的信誉如何传递而不被少数节点合谋放大？
  • 模型质量评估：委派出去的活由不同模型完成，结果质量如何自动核对？
  • 移动端可用性：能耗、后台保活、断网重连与离线队列仍是工程瓶颈。
  • 结算的边界：链上留痕只证明「发生过」，不证明「结果正确」，仍需要可复核的证据链。
